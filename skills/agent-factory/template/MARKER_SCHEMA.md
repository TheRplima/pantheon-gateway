# Placeholder Markers — Template Schema v1.0

## Overview

Templates use structured HTML comment markers to define zones with different editability rules.

## Marker Syntax

```markdown
<!-- :::marker_type:subtype -->
Content here
<!-- ::: -->
```

## Marker Types

### `:::meta`
Template metadata block. Must appear at top of file.

```markdown
<!-- :::meta
template_version: v2.3
marker_schema: v1.0
protected: true  # optional, for essence-shielded files
::: -->
```

### `:::immutable`
Content that **MUST NEVER** be modified by factory or agent.

- Core philosophy statements
- Governance references
- Standard compliance sections
- Closing statements

```markdown
<!-- :::immutable -->
This agent operates under **Pantheon Standard v2.3**.
<!-- ::: -->
```

### `:::customizable:name`
Content that is **filled by Factory** during agent creation using model data.

Subtypes:
- `customizable:identity` — Name, emoji, vibe
- `customizable:principles` — Core truths, can be extended
- `customizable:boundaries` — Behavior limits
- `customizable:vibe` — Communication style
- `customizable:domain` — Domain description
- `customizable:scope` — Allowed/prohibited actions
- `customizable:rules` — Domain-specific rules

```markdown
<!-- :::customizable:identity -->
- **Name:** {{AGENT_NAME}}
- **Emoji:** {{AGENT_EMOJI}}
<!-- ::: -->
```

### `:::onboarding:type`
Content that is **filled by Agent** during first interaction with user.

Subtypes:
- `onboarding:required` — Must be collected before operation
- `onboarding:optional` — May be collected or skipped

```markdown
<!-- :::onboarding:required -->
- **Name:** {{USER_NAME}}
- **Timezone:** {{USER_TIMEZONE}}
<!-- ::: -->
```

### `:::extensible:name`
Content that **may be extended** at runtime by the agent, subject to constraints.

Subtypes:
- `extensible:context` — User context, preferences
- `extensible:specialization` — Agent-specific additions

Rules:
- Requires evidence for updates
- Subject to field allowlists (see model `context.allowed_fields`)
- Max size limits may apply

```markdown
<!-- :::extensible:context -->
## Context
*(Build this over time)*
<!-- ::: -->
```

## Placeholder Variables

Format: `{{VARIABLE_NAME}}`

### Agent Variables (from model)
| Variable | Source |
|----------|--------|
| `{{AGENT_NAME}}` | model.identity.name |
| `{{AGENT_EMOJI}}` | model.identity.emoji |
| `{{AGENT_CREATURE}}` | model.identity.creature |
| `{{AGENT_VIBE}}` | model.identity.vibe |
| `{{AGENT_TYPE}}` | model.type (ENTRY/SERVICE) |
| `{{AGENT_DOMAIN}}` | model.domain |
| `{{NEXUS_ID}}` | Generated by factory |
| `{{AGENT_PURPOSE}}` | model.soul.purpose |
| `{{AGENT_PRINCIPLES}}` | model.soul.principles (formatted) |

### User Variables (from onboarding)
| Variable | Collected |
|----------|-----------|
| `{{USER_NAME}}` | First interaction |
| `{{USER_PREFERRED_NAME}}` | First interaction |
| `{{USER_TIMEZONE}}` | First interaction |
| `{{USER_LANGUAGE}}` | First interaction |

## Processing Order

1. Factory loads template
2. Factory loads model
3. Factory substitutes `{{VARIABLE}}` placeholders in `customizable` zones
4. Factory generates agent workspace
5. Agent collects `onboarding` data on first run
6. Agent extends `extensible` zones over time

## Validation Rules

1. `immutable` zones must not be modified after generation
2. `customizable` zones may only be modified by re-running factory with `--force`
3. `onboarding` zones may only be updated during bootstrap
4. `extensible` zones require evidence for updates
5. Missing required onboarding fields block normal operation
